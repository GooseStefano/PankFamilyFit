# Pank Family Fit v1.2.0

Мобильный дневник КБЖУ для Дани и Вики. Реализован как React/Vite-приложение с Supabase-синхронизацией и безопасным localStorage fallback; SQL-схема находится в `supabase/schema.sql`.

Production: [https://pank-family-fit.vercel.app](https://pank-family-fit.vercel.app)

## Запуск

```bash
npm install
npm run dev
```

## v1.2.0 — живой дневниковый редизайн Today screen

Экран «Сегодня» визуально приблизился к семейному референсу: приветствие стало теплее, послание дня — компактнее, а блок КБЖУ получил круговой индикатор калорий и ровную сетку макронутриентов. Приёмы пищи, заметка и список заботы стали плотнее и больше похожи на строки личного дневника. Точечные рукописные подписи используют только системные fallback-шрифты и не мешают основному читаемому тексту.

Graphite+pistachio Дани и graphite+soft rose Викуси сохранены. Геометрия остаётся в системе 4/6/8 px, нижняя навигация — плоской, а business logic, Supabase, RLS, структура данных, Edge Functions, offline snapshot и PWA update flow не менялись.

## v1.1.0 — визуальный редизайн без типового AI-глянца

Интерфейс стал больше похож на личный домашний дневник: компактнее, прямее и спокойнее. Крупные карточки ограничены радиусом 8 px, поля и кнопки — 6 px, небольшие метки — 4 px. Убраны декоративные градиенты, glass/blur, лишние тени и капсульные состояния; нижняя навигация теперь выглядит как плоская панель с верхней линией активного раздела.

Темы сохранены: у Дани graphite + pistachio, у Викуси — мягкая розовая палитра. Обе используют одинаковую геометрию, контрастные focus-состояния и tap targets 44–48 px. Релиз не меняет бизнес-логику, Supabase, RLS, структуру данных, Edge Functions, offline snapshot и PWA update flow.

## Обновления PWA v0.19.0

В «Настройках» есть блок «Версия и обновления»: номер текущей сборки, режим данных, статус сети и время последней успешной синхронизации с Supabase. Когда service worker загрузит новую версию при доступном интернете, появится кнопка «Обновить». Она активирует подготовленное обновление и перезагружает приложение.

Если телефон продолжает показывать старую версию, откройте PWA или сайт при включённом интернете, подождите несколько секунд и откройте «Настройки». При появлении уведомления нажмите «Обновить». Не очищайте данные сайта для этого: это удалит офлайн-снимок. Оффлайн-режим по-прежнему доступен только после хотя бы одного успешного онлайн-запуска; в офлайне обновление не предлагается.

## План КБЖУ и корректировки v0.17.0

В настройках Дани появился отдельный блок «План КБЖУ»: текущие цели, дата начала, создание новой цели на прошлую или будущую дату, причина и необязательный комментарий. Старые цели остаются в истории вместе с КБЖУ, датой и автором изменения. Вика сохраняет прежнее ограничение: в текущем интерфейсе план КБЖУ меняет только Даня.

Подсказка опирается на последние 14 дней с едой и измерениями веса, ничего не меняет автоматически и не даёт медицинских обещаний. Недельный отчёт показывает цель для каждого дня и считает сводный план только по дням с едой: пропущенные дни не становятся искусственным дефицитом.

Для Supabase примените [миграцию nutrition goal history](supabase/migrations/20260916_nutrition_goal_history.sql). Она добавляет `reason`, `comment` и `created_by` в существующую `nutrition_goals`. Эти поля уже входят в localStorage, offline snapshot и JSON backup/import вместе с объектами целей.

Обычный порядок — избранные, затем часто используемые продукты. Карточка показывает тип, категорию, КБЖУ на 100 г/мл, меры, число использований и архивный статус.

Новые таблицы и миграция не нужны: используются существующие поля продуктов, поэтому localStorage, offline snapshot и JSON backup/import продолжают работать без изменений структуры.

## Шаблоны еды и быстрые порции v0.15.0

LocalStorage, offline snapshot и JSON backup уже включают эти данные.

## Тренировки 2.0 v0.14.0

Дневник тренировок Дани теперь сопоставляет упражнение с прошлой тренировкой той же недели и группы мышц: сначала по упражнению из библиотеки, а для старых записей без него — по названию. В раскрывающемся блоке упражнения доступны прошлый результат, выполненные подходы, лучший вес, повторы, объём и краткая история последних выполнений.

Подсказки на следующую тренировку зависят только от заполненных подходов, тяжести и изменения объёма. Это осторожные ориентиры, а не медицинские или тренерские обещания. Всё рассчитывается из имеющихся `workout_sessions`, `workout_exercises` и `workout_sets`, поэтому миграция не нужна; те же данные входят в Supabase/localStorage и офлайн-снимок.

## Цель веса и план снижения v0.13.0

## Установка как PWA

Перед установкой откройте опубликованную HTTPS-версию приложения и войдите хотя бы один раз, чтобы на устройстве сохранился последний локальный снимок.

Для проверки на физическом телефоне нужен HTTPS. `npm run preview -- --host 0.0.0.0` удобен для проверки layout по сети Wi‑Fi, но адрес вида `http://192.168.x.x` не является secure context на iPhone или Android: браузер не зарегистрирует service worker, поэтому installation/offline PWA там не проверяются корректно. Для настоящего теста используйте production URL с HTTPS.

1. Откройте приложение именно в Safari.
2. Нажмите «Поделиться».
3. Выберите «На экран “Домой”» и подтвердите добавление.

### Android

1. Откройте приложение в Chrome.
2. Откройте меню браузера и выберите «Установить приложение» (иногда пункт называется «Добавить на главный экран»).
3. Подтвердите установку.

В Supabase-режиме PWA после каждой успешной загрузки и подтверждённой записи сохраняет отдельный локальный снимок. Оффлайн-режим работает только после хотя бы одного успешного онлайн-запуска с действующим PIN-сеансом. Если снимка ещё нет, приложение честно покажет: «Нет сохранённого снимка. Откройте приложение онлайн хотя бы один раз.»

## Supabase sync v0.7.0

1. Создайте проект Supabase и примените весь файл `supabase/schema.sql` в SQL Editor.
2. Скопируйте `.env.example` в `.env.local` и задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
3. В Supabase CLI добавьте серверные секреты: `PANK_SERVICE_ROLE_KEY` и `PIN_JWT_SECRET` (значение JWT Secret проекта). Не добавляйте их в Vite env или репозиторий.
4. Задеплойте PIN-функцию: `supabase functions deploy pin-login --no-verify-jwt`.
5. Перезапустите `npm run dev`. При заданных Vite-переменных приложение показывает «Синхронизация Supabase» и загружает данные из базы.

PIN никогда не записывается в localStorage и не находится в клиентском коде. В production клиент передаёт введённый PIN только в Edge Function `pin-login` по HTTPS. Функция сравнивает SHA-256 хэш с `pin_access`, выдаёт короткоживущий signed JWT с user/role claims, а RLS ограничивает строки. Не используется Supabase Auth, email, пароль или регистрация. В local fallback оставлены только SHA-256 хэши для dev-входа; не используйте его как production-авторизацию.

Слой `src/services/storage.js` выбирает реализацию. `localStorageService.js` и `supabaseService.js` предоставляют общий API загрузки, сохранения, входа и выхода, поэтому компоненты не знают, где лежат данные. Обновления применяются оптимистично; при конфликте действует last write wins по `updated_at`. При проблеме сети остаётся текущий экран, появляется мягкая ошибка с кнопкой «Повторить».

## Проверка production sync v0.7.1

## Полировка конструктора рецептов v0.4.1

Карточки ингредиентов поддерживают поиск по базе, изменение продукта и количества на месте, быстрый выбор доступной меры, дублирование и удаление с подтверждением. Новый ингредиент всегда начинается с пустых полей, а после выбора продукта форма предпочитает граммы, затем миллилитры и только потом базовую штучную меру.

Предпросмотр дополнен готовым весом и примерами порций на 100 и 300 г. Некорректные и нечисловые значения не попадают в расчёт. Если готовый вес составляет меньше половины суммы базовых количеств ингредиентов, форма показывает предупреждение, но позволяет сохранить проверенный пользователем рецепт.

При редактировании заранее показан номер новой версии. Если блюдо уже использовалось, форма поясняет, что история дневника сохранит прежние значения, а уведомление после сохранения подтверждает это.

## Supabase

Примените `supabase/schema.sql` в SQL Editor. Для безопасной production-версии PIN нельзя проверять запросом к таблице из браузера: добавьте Edge Function для проверки PIN и выдачи короткоживущего JWT, затем RLS-политики по `user_id` и `role`. До настройки backend приложение намеренно работает в локальном режиме.
