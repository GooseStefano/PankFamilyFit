# Pank Family Fit v0.4.0

Мобильный дневник КБЖУ для Дани и Вики. Реализован как React/Vite-приложение с локальным демо-хранилищем; SQL-схема Supabase находится в `supabase/schema.sql`.

## Запуск

```bash
npm install
npm run dev
```

Данные демо-режима сохраняются в `localStorage`, включая запомненный вход. PIN-коды в клиентском коде представлены только SHA-256 хэшами.

## Что входит

- PIN-вход и запоминание устройства;
- роли admin/member и переключение профиля у Дани;
- дневник по четырём приёмам пищи;
- расчёт и неизменяемый снимок КБЖУ;
- редактирование, перенос по дате/приёму и удаление записей;
- история дней и комментарии;
- база продуктов, поиск, категории, любимые, архивирование;
- создание продуктов, простых блюд и домашних блюд из ингредиентов;
- история целей по дате;
- недельный отчёт по КБЖУ с планом, фактом, разницей и средними значениями;
- оценка недели и детализация по дням с учётом истории целей;
- трекер веса для Дани и Вики с периодами 7 / 30 дней / всё время;
- график веса, недельное среднее и изменения за неделю и месяц;
- интерфейс Graphite & Pistachio в mobile-first контейнере;
- подтверждения опасных действий, пустые состояния и короткие уведомления.

## Недельный отчёт v0.2

В разделе «История» доступны два режима: недельный отчёт и список дней. Неделя считается с понедельника по воскресенье. План каждого дня формируется из цели КБЖУ, которая действовала именно на эту дату, поэтому изменение цели в середине недели корректно влияет только на последующие дни.

Даня может переключать отчёт между своим профилем и профилем Вики. Вика видит только собственные данные.

- [ ] Из прошлой недели можно перейти вперёд и вернуться кнопкой «К текущей неделе»
- [ ] Неделя начинается в понедельник и заканчивается в воскресенье
- [ ] План, факт и разница рассчитаны для Ккал / Белков / Жиров / Углеводов
- [ ] Среднее КБЖУ рассчитано по семи календарным дням

## Трекер веса v0.3.0

Раздел «Вес» хранит одно измерение на профиль и дату. Даня может переключаться между своими записями и записями Вики, а Вика работает только со своим весом. При попытке сохранить вторую запись на ту же дату приложение предлагает заменить существующую.

График построен как адаптивный SVG и показывает точки только для сохранённых измерений. Среднее текущей недели считается с понедельника по воскресенье только по дням с записями. Изменения за неделю и месяц сравнивают последний вес с ближайшим измерением не позднее даты семь или тридцать дней назад.

### Чеклист проверки веса

- [ ] Даня переключает вес между своим профилем и профилем Вики
- [ ] Вика видит и редактирует только собственный вес
- [ ] Последний вес отображается с датой
- [ ] Изменение за неделю использует точную или ближайшую более раннюю запись

- [ ] При недостатке данных для изменения показано понятное состояние
- [ ] Средний вес недели учитывает только дни с измерениями
- [ ] График переключается между 7 днями / 30 днями / всем временем

## Блюда из ингредиентов v0.4.0

Даня может создать домашнее блюдо из продуктов базы, указать количество и меру каждого ингредиента, а затем ввести общий вес готового блюда. Приложение суммирует КБЖУ ингредиентов и автоматически рассчитывает значения на 100 г готового блюда. Сохранённый рецепт становится обычным блюдом в базе и доступен при добавлении еды в дневник.

Состав рецепта хранится отдельно в `recipe_ingredients`. Каждая строка содержит snapshot КБЖУ ингредиента на момент сохранения. Редактирование рецепта повышает номер версии и обновляет текущие значения блюда, но уже добавленные записи дневника не меняются, потому что `meal_entries` также хранит собственный snapshot.

Вика через форму добавления еды может создать продукт или простое блюдо. Конструктор блюд из ингредиентов доступен только Дане в разделе «Продукты».

### Чеклист проверки блюд из ингредиентов

- [ ] У Дани доступны кнопки «Продукт», «Простое блюдо» и «Из ингредиентов»
- [ ] У Вики нет раздела «Продукты» и конструктора рецептов
- [ ] Вика может создать продукт или простое блюдо через «Добавить еду»
- [ ] Категория нового рецепта по умолчанию — «Готовое»
- [ ] В рецепт добавляются 2–3 ингредиента из базы
- [ ] Для каждого ингредиента доступны его существующие меры
- [ ] КБЖУ ингредиента пересчитывается при изменении количества или меры
- [ ] Предпросмотр показывает общий КБЖУ и расчёт на 100 г
- [ ] Расчёт на 100 г соответствует формуле `итого / готовый вес × 100`
- [ ] Кнопка сохранения неактивна без названия, веса или корректных ингредиентов
- [ ] Показаны состояния: нет ингредиентов, не выбран продукт, неверное количество и неверный готовый вес
- [ ] Сохранённое блюдо появляется в базе с пометкой рецепта и номером версии
- [ ] Сохранённое блюдо можно добавить в дневник как обычный `food_item`
- [ ] Запись дневника сохраняет snapshot КБЖУ
- [ ] Редактирование веса или состава рецепта пересчитывает КБЖУ и повышает версию
- [ ] Старая запись дневника не меняется после редактирования рецепта
- [ ] Архивирование рецепта скрывает его из базы, но не удаляет старую запись дневника
- [ ] Ингредиенты сохраняют snapshot КБЖУ в `recipe_ingredients`
- [ ] После создания и обновления показано уведомление
- [ ] Форма помещается на ширине 375 px и в landscape без горизонтальной прокрутки
- [ ] `npm run build` завершается успешно, консоль браузера без ошибок

## Supabase

Примените `supabase/schema.sql` в SQL Editor. Для безопасной production-версии PIN нельзя проверять запросом к таблице из браузера: добавьте Edge Function для проверки PIN и выдачи короткоживущего JWT, затем RLS-политики по `user_id` и `role`. До настройки backend приложение намеренно работает в локальном режиме.
